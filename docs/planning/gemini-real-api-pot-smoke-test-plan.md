# Gemini 真实 API 与 Pot GUI 烟测计划

## 1. 目标

本计划用于在 Windows 10 + Pot Desktop 环境中，对已经合并到 `main` 的 Gemini Key 池与 Interactions API 功能进行一次小规模、人工、可回退的真实 API 烟测。

验证重点：

1. 用户能够在 Pot 插件设置页正确填写 Gemini API Key；
2. `aiMode=off` 时保持零网络调用；
3. `unknown_only` 仅在本地存在未知 token 时调用 Gemini；
4. 成功响应会在本地结果末尾增加“AI 语义增强”；
5. Gemini 请求失败时仍完整保留本地结果；
6. `gemini_state.db` 仅保存 Key 指纹和调度状态，不保存明文 Key、用户输入或模型输出；
7. 全程不把真实 API Key 写入 Git、命令行、终端输出、日志、截图、录屏或聊天。

本计划不是自动化压力测试，不用于验证配额上限，也不允许循环调用真实 Gemini API。

## 3. API Key 填写位置

安装插件后，在 Pot 中打开：

```text
偏好设置
→ 服务设置
→ 翻译
→ 程序员划词翻译
→ 打开该插件的配置页面
```

找到字段：

```text
Gemini Key 池（设置页明文，# 前缀禁用）
```

单 Key 推荐填写格式：

```text
主要=<用户本人粘贴真实 Key>
```

多 Key 格式：

```text
主要=<KEY_1>
备用=<KEY_2>
#停用=<KEY_3>
```

支持换行、英文逗号、中文逗号或分号分隔，最多 20 个唯一 Key。`#` 前缀表示禁用。名称只用于本地辨认，不发送给 Google。

重要限制：Pot 当前外部插件设置页没有密码输入框，Key 可能以明文显示。真实 Key 必须由用户本人在设置页粘贴；本地 AI 不得要求用户在聊天中发送 Key，也不得复制、读取、回显或记录 Key。

## 4. 推荐设置

首次真实 API 烟测使用：

```text
Gemini 语义增强：仅本地未知词
Gemini Key 池：主要=<用户本人粘贴>
单次最多尝试不同 Key 数：1
Gemini 模型：Gemini 3.5 Flash-Lite（默认）
自定义 Gemini 模型 ID：留空
Gemini 发送范围：仅 token（默认）
输出格式：完整分析
```

先将“单次最多尝试不同 Key 数”设为 `1`，避免首次测试因配置错误触发多个真实 Key 请求。确认单 Key成功后，再按需测试 Key 池切换。

## 5. 安全边界

### 5.1 允许

- 用户本人在 Pot 设置页手动粘贴真实 Gemini API Key；
- 本地 AI 指导用户点击设置、执行少量查询并记录脱敏结果；
- 使用 1—3 次真实 API 请求验证成功路径；
- 检查插件输出中是否出现“AI 语义增强”；
- 搜索并只读检查 `gemini_state.db` 的文件位置、表名和非敏感字段；
- 截图查询结果，但截图中不得出现插件设置页 Key 字段。

### 5.2 禁止

- 将真实 Key 写入仓库、`.env`、脚本、命令行参数、PowerShell 历史、测试文件或临时文本；
- 在聊天、日志、截图、录屏、终端输出中显示完整 Key或 Key 尾号；
- 修改源码、提交、push、创建分支或 PR；
- 使用真实 API 执行自动化单元测试、循环测试、并发测试或配额压力测试；
- 抓取或打印完整 HTTP 请求头；
- 上传 `gemini_state.db`；
- 为了观察切换行为而故意高频触发 429。

## 6. 测试阶段

### 阶段 A：安装与设置确认

1. 安装指定 `.potext`；
2. 确认翻译服务列表中存在“程序员划词翻译”；
3. 确认设置页存在以下字段：
   - Gemini 语义增强；
   - Gemini Key 池（设置页明文，# 前缀禁用）；
   - 单次最多尝试不同 Key 数；
   - Gemini 模型；
   - 自定义 Gemini 模型 ID；
   - Gemini 发送范围；
4. 不截图 Key 输入框；
5. 用户本人粘贴 Key 并保存。

通过标准：字段完整、默认模型正确、设置可保存。

### 阶段 B：本地零网络基线

将“Gemini 语义增强”设置为“关闭”，测试：

```text
translate_service_list
getIPv6Address
```

通过标准：

- 输出包含本地拆分、编程含义、普通词义与命名格式；
- 不出现“AI 语义增强”；
- 不因已填写 Key 而自动调用 Gemini。

### 阶段 C：unknown_only 本地命中

将“Gemini 语义增强”设置为“仅本地未知词”，测试：

```text
translate_service_list
```

通过标准：

- 本地全部命中时不出现“AI 语义增强”；
- 输出与本地结果一致；
- 不产生远端错误提示。

### 阶段 D：真实 API 成功路径

使用一个本地词典大概率未收录、但不包含项目、文件路径或源码上下文的人工 token，例如：

```text
elioSemanticProbeToken
```

不得使用公司名称、真实项目名称、客户信息、文件路径、源码行、账号、聊天内容或其他敏感文本。

通过标准：

- 本地结果仍完整显示；
- 末尾新增：

```text
AI 语义增强：……
AI 未知词：……
```

- 不显示 API Key；
- 不显示完整远端请求或错误堆栈；
- Pot 不白屏、不崩溃、不阻断其他翻译服务。

首次成功后只需再请求一次同类无敏感 token，确认功能可重复使用，随后停止真实 API 测试。

### 阶段 E：失败回退

优先使用无网络方式验证：

1. 保持 Key 不变；
2. 临时断开网络或在系统层阻断联网；
3. 查询一个未知 token；
4. 恢复网络。

通过标准：

- 查询仍返回完整本地结果；
- 不出现白屏或无限等待；
- 不在输出中泄漏 Key 或请求头；
- 不要求用户重复提交查询。

不建议为了本次验收故意使用错误真实 Key。只有用户已经拥有可安全废弃、明确会返回 401/403 的测试 Key 时，才可在用户明确同意后进行可选切换测试。

### 阶段 F：状态数据库只读检查

关闭 Pot 后，在 Pot 用户数据目录中搜索：

```text
gemini_state.db
```

只允许读取：

- 文件实际路径；
- 文件大小；
- 表名；
- 字段名；
- 记录数量；
- fingerprint 是否为 64 位十六进制 SHA-256；
- status、cooldown_until、rate_limit_count、last_success_at、updated_at；
- active_fingerprint。

禁止输出：

- 数据库完整二进制；
- 任何明文 Key；
- 用户输入；
- 模型输出；
- 可用于反推 Key 的自定义额外信息。

通过标准：数据库中只存在指纹与调度状态，不存在 `api_key`、`key_tail`、`input`、`prompt`、`response`、`model_output` 等敏感字段。

## 7. 可选 Key 池验证

只有用户拥有至少两个自己管理的有效 Key 时才执行：

1. 设置：

```text
主要=<KEY_1>
备用=<KEY_2>
```

2. `maxKeyAttempts=1`，完成一次成功请求；
3. 改为 `maxKeyAttempts=2`；
4. 不人为制造 429，不做高频请求；
5. 只检查状态库中 active fingerprint 是否存在，不尝试根据指纹识别 Key；
6. 若需要验证 `#` 禁用，仅在设置页给备用 Key 前加 `#`，确认插件仍可用。

不要求在本轮验收中强制触发自动切换。401/403、429、408、5xx 和网络异常切换已由 mock 强契约测试覆盖。

## 8. 停止条件

出现以下任一情况立即停止真实 API 请求并回报：

- Pot 白屏、崩溃或翻译服务无法恢复；
- 输出或日志出现完整 Key；
- 请求持续超过 30 秒仍无结果；
- 连续两次真实 API 请求失败；
- 返回 400 或 404；
- 返回 401/403 且用户确认 Key 在 Google AI Studio 中有效；
- 返回 429；
- 出现无法解释的数据库敏感字段；
- 本地结果被远端失败覆盖或删除。

不得通过连续重试掩盖失败。

## 9. 验收证据

本地 AI 最终只回传：

1. 操作系统与 Pot 版本；
2. 插件版本来源、目标 SHA、Artifact ID；
3. 每个场景通过/失败；
4. 脱敏后的输入和输出；
5. 是否出现“AI 语义增强”；
6. 是否完整保留本地结果；
7. `gemini_state.db` 路径、表名、字段名和记录数量；
8. 原始错误类型与状态码，但不得包含请求头或 Key；
9. 截图文件名，截图中不得出现 Key 设置页。

不得回传 API Key、Key 尾号、完整请求头、数据库文件或含 Key 的截图。

## 10. 测试后处理

完成后：

1. 将“Gemini 语义增强”恢复为“关闭”，除非用户明确希望继续使用；
2. 用户自行决定是否保留 Key；
3. 若不继续使用，由用户本人在设置页清空 Key 池；
4. 不删除仓库文件、不修改代码；
5. 不自动删除 `gemini_state.db`，只记录其存在和内容边界；
6. 将测试结果交给网页端 ChatGPT 判断是否需要后续修复 PR。
